# Spec — Checklist Engineer v0.1

## Problem statement

Experts performing complex work can miss known critical actions or fail to exchange necessary information. Existing “checklists” often become bloated process manuals, generic to-do lists, or mechanical box-ticking forms.

We need an agent skill that reliably turns real failure patterns into concise operational checklists while preserving professional judgment.

## Solution

Create one installable `checklist-engineer` skill with progressive disclosure for three branches:

1. design a checklist;
2. audit an existing checklist;
3. plan a field test.

All branches share the same domain vocabulary and stable output contract.

## User stories

1. Given a workflow and known failure pattern, the agent identifies whether checklisting is appropriate.
2. The agent defines an explicit pause point before drafting items.
3. The agent chooses READ-DO or DO-CONFIRM and explains the choice briefly.
4. The agent rejects low-value items that are important but not plausibly omitted.
5. The agent adds communication checks when uncertainty crosses roles or expertise.
6. The agent preserves named areas of professional judgment.
7. The agent produces concise, executable wording.
8. The agent flags a checklist that behaves like an SOP/manual.
9. The agent produces a field-test plan rather than treating draft v1 as final.
10. The agent evaluates outcomes and catches, not only checkbox completion.

## Implementation decisions

- One skill, not three.
- `skills/checklist-engineer/SKILL.md` is the installable entry point.
- Branch details live in sibling `references/`.
- `CONTEXT.md` owns domain vocabulary.
- `AGENTS.md` is a pointer layer.
- GitHub Issues is the backlog.
- No copy of the source book is stored in the repository.

## Testing decisions

Test the stable output seam using the manual acceptance cases in `tests/acceptance.md`.

A case passes only when the resulting artifact contains the required contract fields and does not violate the non-negotiables.

## Out of scope

- Teaching a novice the full underlying procedure.
- Automatically proving the medical, legal, engineering, or safety validity of domain-specific items.
- Replacing a subject-matter expert.
- Quantitative risk scoring presented as if it came from Gawande.
- A UI or hosted application.
